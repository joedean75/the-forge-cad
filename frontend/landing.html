Two kernels

Exact first. The field when it has to be.

A dimension should be right because the geometry is right, not because you meshed it finely enough. Forge never mixes the two in one body — half exact and half approximated is worse than either.

Faces and edges you can click and measure. Resolution stops changing the answer and only controls how smoothly a curve is drawn.

Where it wins

Distance fields

What implicit geometry does better, with a native Rust sampler on the hot path.

  • Density fields from the topology optimizer

  • Smooth blends between separate bodies

Output

It leaves as something a machine reads.

A part that can only be admired in a viewport is not finished. Every format below comes off the same body, measured on the exact geometry.

STEP

Analytic solids from the B-rep kernel — the file a supplier quotes from, not a faceted approximation of one.

DXF

Flat patterns with the outline on CUT and bend lines on BEND, so the laser cuts the blank and marks the folds.

G-code

FDM slicing, 2.5D milling, and kerf-compensated profile cutting, posted to the dialect your machine speaks.

Drawings

Dimensioned views with GD&T and ISO-286 fits, as SVG to read or DXF the next tool can measure.

For agents

Parity, not a plugin.

Every tool in the ribbon runs an operation from the catalog. An agent reads that same catalog — typed arguments, JSON Schema, what each one is for — and calls them over REST or MCP. Same code path, so if a person can do it, an agent can.

Operations verify their own work, so an agent can check the body it just built instead of assuming.
